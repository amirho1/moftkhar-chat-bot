# Configuration without editing application code

Public settings live in `config/starter.json`. `organization` controls the public name, website and verified human-support URL; `ui` controls locale, title, greeting, privacy hint, suggested questions, theme and color. `knowledge` names an approved file or native Website configuration and a sync interval. `agent` bounds context/history and rolling 24-hour agent token/request quotas. `links` restricts citation hosts and paths. These settings must contain no secrets or customer data.

Private values belong in `.env` (or a secret manager supplying the same environment variables). Setup derives `.runtime/native.env` or `.runtime/docker.env` without printing values. Preserve `JWT_SECRET_KEY`, `ENCRYPTION_SECRET_KEY`, `INTERNAL_KEY` and `CHAT_SESSION_SECRET` across restarts and redeployments. Changing an encryption key can make saved provider/tool credentials unreadable. Rotate deliberately using the pinned DocsGPT procedure and test restoration.

`OPENAI_BASE_URL`, `API_KEY`, `LLM_NAME` select an authorized OpenAI-compatible **chat** provider. They do not select embeddings. A `/models` entry or HTTP 200 does not prove a usable response; test actual content, streaming and supported parameters. There is no automatic substitute provider, public demo key, or billing change.

The default embedding model is `ibm-granite/granite-embedding-97m-multilingual-r2`, with FAISS vectors, PostgreSQL metadata and Redis. It runs locally in the required worker. Use the same embedding configuration for documents and queries. Model changes require re-embedding, not merely restarting. This is separate from answer-language prompting and UI localization.

For optional model reasoning/output caps, use the pinned DocsGPT operator catalog feature (`MODELS_CONFIG_DIR`) and a private YAML. The supported schema uses `provider: openai_compatible`, `api_key_env`, `base_url`, model `id`/`upstream_model_id`, and capabilities such as `reasoning_effort`, `max_output_tokens`, `context_window`, `first_token_timeout`, `stall_timeout`, and `answer_timeout`. Set `LLM_NAME` to the catalog's local model ID and keep `OPENAI_BASE_URL` empty: the YAML supplies its own base URL. Combining a catalog with the legacy `OPENAI_BASE_URL`/`LLM_NAME` configuration can register the same ID again and lose its reasoning/output capabilities. `api_key_env` may name a custom server-only secret (for example `API_PROXY_TOKEN`); no copy into frontend configuration is required. Mount the catalog for every backend/worker that uses it. Verify provider-specific behavior and actual outbound requests before deployment. Do not put a particular organization/provider's catalog in public starter defaults.

The generic agent is a native Classic agent: input limits → approved retrieval → one concise answer with evidence → clarification/support when needed. It has no administrative, ordering, refund, general browsing or live pricing tool. An organization may supply a separate reviewed read-only adapter in a private overlay; never expose admin Payload, hosting, browser or GitHub sessions to the public agent.

For a Website source, create a reviewed config with explicit HTTPS hosts, narrow `path_prefix`, bounded `max_pages`, no subdomain wildcard, sitemap discovery, and skip rules for account/admin/checkout/private routes. Set `knowledge.mode` to `website` and `websiteConfig` to that file. Native DocsGPT performs bounded SSRF-protected fetching, extraction and synchronization; verify its removal/partial-failure behavior with your source. Enable Docker profile `website-sync` only for website mode. The TypeScript synchronizer takes a Redis lease, defaults to six hours, and keeps last success plus failure status in `starter:sync:status`. Never give it logged-in browser cookies.

`CHAT_ENABLED=false` is the runtime kill switch. The browser receives only public UI settings, not the provider key, agent key, backend URL or management token. Per-session/per-network/global hourly limits share Redis and fail closed if unavailable. Do not trust forwarded IP headers until your ingress overwrites them and the app cannot be reached directly. Keep HTTP access local; production needs HTTPS and secure session cookies.
